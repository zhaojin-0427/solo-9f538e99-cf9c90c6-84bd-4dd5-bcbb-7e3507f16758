# 夜骑问卷核查（Flask）

同一套夜骑问卷，两台调查终端可能因为配置版本不同或问卷逻辑异常，**填相同的筛查答案却出现不同的跳题**。
本工具包含两个互相独立的核查页：

1. **旧答卷夜骑纳入核查**：上传旧版答卷的已答筛查项与展示/跳过记录，判断哪些未答筛查项的补全
   能与旧档相符，并以**最少的最坏补问题数**推荐电话补问题目。
2. **试跑核查**（`/trials`）：上传带版号的问卷配置与试跑 JSONL，同版同答案的一组试跑中，
   只有**来自不同终端**且**一份显示、一份跳过**才报异常，并给出证据对与哪份不符该版规则。

## 一、判定逻辑

### 条件语言（至多 12 个是非筛查项）

- 变量：字母/下划线开头的标识符，如 `S1`、`X_1`
- 与：`AND` / `&&` / `&` / `与` / `且`
- 或：`OR` / `||` / `|` / `或`
- 非：`NOT` / `!` / `~` / `非`（支持紧贴写法，如 `非S1`、`S1或S2`）
- 括号 `( )` 与常量 `true/false`（也可写 `真/假`、`是/否`、`1/0`）
- 优先级：`非` > `与` > `或`，括号可改变优先级
- 示例：`S1 AND (S2 OR NOT S3)`、`非S1 与 (S2 或 S3)`

### 约束与补全

n 个筛查项共 2^n 种真值组合（n ≤ 12，即最多 4096 种），逐一枚举并过滤：

1. 已答筛查项：补全必须与答案一致；
2. 当时**展示过**的追问题：其展示条件在补全下必须为**真**；
3. 当时**跳过**的追问题：其展示条件在补全下必须为**假**。

过滤后：

- **无可行补全** → 旧档矛盾，页面给出一个极小（每个约束都必不可少的）矛盾核，
  列出需要优先电话核对的记录；
- **可行补全的纳入结论全部一致** → 直接判定“纳入/不纳入”，无需再打电话；
- **结论仍有分歧** → 用 minimax 决策树计算“从当前状态起最坏还要问几题”，
  推荐使该题数最小的未答筛查项；被现有约束唯一确定的未答项会标为“隐含”，无需再问。

每回答一题立即重新判定；若新答案与旧档冲突，拒绝该提交、提示冲突约束，并保留提交前
的结果与全部历史答案。

## 二、数据格式

### 配置（可与答卷合并上传，键为 `config` / `archive`）

```json
{
  "items": ["S1", "S2", "S3"],
  "labels": {"S1": "夜间佩戴头盔", "S2": "配有车前灯", "S3": "单次夜骑超30分钟"},
  "followups": [
    {"qid": "Q1", "condition": "S1 AND NOT S2", "shown": true},
    {"qid": "Q2", "condition": "S3 OR S1", "shown": false}
  ],
  "inclusion": "S1 AND (S2 OR S3)"
}
```

- `shown` 为配置阶段的初值，上传答卷后以答卷记录为准重建。

### 旧答卷

```json
{
  "answers": {"S1": true},
  "followups": [
    {"qid": "Q1", "shown": true},
    {"qid": "Q2", "shown": false}
  ]
}
```

- 必须列出配置中的**全部**追问题号（展示或跳过都要显式记录），缺号会报错，
  避免“没列出”与“明确跳过”产生歧义；
- 兼容只给 `shown_qids`（展示题号数组）的简化形式。

完整示例见 `sample/config_with_archive.json`、`sample/archive_only.json`。

## 二·五、试跑核查（`/trials`）

### 版号配置

支持单版号对象、`{"versions": [...]}` 或版号映射 `{"v1": {...}}`：

```json
{
  "versions": [
    {
      "version": "v2.3",
      "items": ["S1", "S2", "S3", "S4"],
      "labels": {"S1": "夜间佩戴头盔"},
      "followups": [
        {"qid": "Q1", "condition": "S1 AND NOT S2"},
        {"qid": "Q2", "condition": "S3 OR S4"}
      ]
    }
  ]
}
```

已有试跑记录的版号不允许改动筛查项集合或增删追问题号；仅修改展示条件时，
该版号的全部答案组会重算一次预期。

### 试跑 JSONL

每行一条，字段别名同时接受英文与中文（`trial_id/试跑号`、`terminal/终端号`、
`version/版号`、`answers/筛查答案`、`followups/展示跳过记录`）：

```json
{"trial_id":"R1001","terminal":"T-A","version":"v2.3",
 "answers":{"S1":true,"S2":false,"S3":true,"S4":true},
 "followups":[{"qid":"Q1","shown":true},{"qid":"Q2","shown":true}]}
```

- 答案必须**完整**覆盖该版全部筛查项；逐题记录必须**显式**列出全部追问题号（展示或跳过），
  缺号/多号都会拒绝，避免“没记”与“明确跳过”混淆；
- 同一试跑号重传**相同内容**不增计；内容不同**不会覆盖**，需在网页按试跑号更正；
  一批中任意一行不合法，整批不写入，原报告保持可查。

### 异常判定与证据

同版号 + 同一组完整答案内的试跑为一组；对每个追问题号，若展示侧与跳过侧各有来自
**不同终端**的记录，则该组该题报异常。页面按版号、追问题号筛选并分页，每组列出
一对实测记录（展示侧 / 跳过侧，含试跑号与终端号），并按该版条件指出**哪一份与预期不符**。

### 更正

在“按试跑号查询”中打开记录，直接编辑完整 JSON 后保存：

- 只重算**旧记录与新记录涉及的答案组**，组内通过按终端的聚合计数判断证据，不逐份扫描；
- 原证据失效时自动换一对仍成立的证据，找不到则撤下该异常；
- 更正内容非法或试跑号被改动时拒绝保存，原记录与原异常报告保持不变。

记录与异常组在同一 SQLite 事务中写入，失败整体回滚。

示例：`sample/trial_versions.json` + `sample/trials.jsonl`。

## 三、启动方式

### Docker Compose（推荐）

```bash
SECRET_KEY=$(openssl rand -hex 32) docker compose up --build
# 浏览器打开 http://localhost:8000（试跑核查在 http://localhost:8000/trials）
```

试跑记录与异常组存于 SQLite（容器内 `/data/trials.db`，挂载到命名卷 `trial-data`），
容器重建后仍可查询；本地默认写入仓库下 `data/trials.db`，可用 `TRIAL_DB_PATH` 覆盖。
不设置 `SECRET_KEY` 时使用开发默认值，仅适合本地试用。

### 本地直接运行

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
flask --app 'app.app:create_app' run --debug
```

判定引擎 `app/engine` 仅依赖 Python 标准库，未装 Flask 也可运行演示与引擎测试。

## 四、测试与验证

## 五、目录结构

```
app/
  app.py                 # Flask 路由（配置/答卷上传、补问、冲突保留、重置）+ 应用工厂
  trial_routes.py        # 试跑核查路由（版号配置、JSONL 上传、分页查询、按试跑号更正）
  store.py               # 试跑持久层：SQLite 事务、按终端聚合的异常组维护
  engine/
    conditions.py        # 布尔条件词法/语法解析、AST 求值
    config.py            # 旧档核查的配置与答卷数据模型、校验
    solver.py            # 可行性枚举、极小矛盾核、minimax 最坏题数
    trial.py             # 版号配置与试跑记录的数据模型、规范化、规则预期
  templates/ static/     # 两个核查页
sample/                  # 示例输入（含 trial_versions.json / trials.jsonl）
tests/                   # unittest 测试（Flask 缺失时 Web 用例自动跳过）
scripts/                 # CLI 演示与 Web 冒烟脚本
```

## 六、交付核对：已实现 / 已验证 / 遗留项

### 已实现

- 12 个以内是非筛查项，且/或/非（中英文符号）条件解析、括号与优先级；
- 旧答卷已答项 + 全部追问题展示/跳过记录上传，约束所有可行补全；
- 无可行补全时给出极小矛盾核（旧档矛盾提示）；
- 结论一致时直接判定纳入/不纳入；分歧时 minimax 推荐使最坏剩余题数最少的未答项，
  页面显示“从当前起最坏还要问几题”及每个候选题的最坏题数；
- 任一未答项均可填写并重新判定；冲突答案被拒绝、提示并保留提交前结果；
- 隐含确定项提示、答案清空/会话重置、Docker Compose 启动；
- 试跑核查：带版号配置上传、JSONL 完整性与别名校验、同内容重传去重、
  异内容整批拒绝并引导更正、异终端“一跳一显”异常组、按版号/题号分页查询、
  每组证据对与预期不符标注、按试跑号更正（只重算受影响的组、证据失效自动换对或撤下）。

### 已验证

- 引擎 21 个 unittest 用例全部通过（解析、优先级、跳题真假约束、矛盾核、
  minimax 题数、12 项上限与重复项校验）；
- 试跑核查 32 个用例通过：记录规范化与中文别名、缺项/多项拒绝、同内容重传不增计、
  异内容与同批冲突整批回滚、同终端不一致不报异常、答案组/版号隔离、分页与越界夹取、
  证据替换与撤下、仍成立的证据对保持稳定、同终端多份记录删除后的代表补位、
  跨答案组更正、只重算受影响组、条件变更后预期重算；
- Flask 路由集成测试通过：旧档核查 6 个、试跑核查 7 个，覆盖上传、分页筛选、
  查询、更正、非法更正保留原状态（共 59 个用例；无 Flask 的机器上 Web 用例自动跳过）；
- 120 次随机更正压力测试：按终端聚合计数与实际记录逐条一致（0 处偏差），
  异常组集合与从零重算完全一致；
- 100 组随机配置与独立穷举参考实现交叉比对，最坏题数与推荐结论零偏差；
- 12 项满配性能：无约束约 76ms、最坏（12 个独立与项）约 0.4s；
- CLI 演示跑通“载入旧档 → 分歧推荐 → 补问后纳入 → 冲突补问被拒”，
  以及试跑演示“异常组 → 更正后证据替换”；
- Web 冒烟脚本在本机以真实 gunicorn/Flask 服务实跑通过（旧档核查 3 步 + 试跑核查 4 步）；
- 边界场景：无追问题、全跳过记录、恒真/恒假条件、无关变量不计入题数、空库分页。

### 遗留项 / 已知边界

- 本机环境无 Docker 守护进程，`docker compose up --build` 未实跑；Dockerfile/compose
  已按同一启动命令用本地 gunicorn 等价验证，建议在有 Docker 的环境再执行一次；
- 旧档核查的会话存于签名 cookie，为单调查员临时核查设计；试跑记录与异常组存于
  SQLite（WAL），支持多 worker，但仍是单机部署，未做多用户权限；
- 极小矛盾核返回其中一个极小核（非全局最小基数核）；12 项规模下二者差异
  对电话核对流程无实际影响；
- 试跑异常按“同版 + 同完整答案”分组；若两台终端连版号都不同，不会互相比较，
  需先确认版号本身是否用错。
